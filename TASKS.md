# TASKS.md

Sequenced implementation plan for the system specified in `REQUIREMENTS.md` and designed in `DESIGN.md`. Each task is sized for one focused Claude Code session (~30–90 min, including tests written alongside the code). Tasks are ordered so the repo is runnable — tests for everything built so far pass — at every boundary. Phase boundaries are the strongest stoppable points.

Locked stack decisions from the Phase-3 clarifying round (see §7 for the AI/me split convention):
- **Python dep manager:** `uv` (pyproject.toml + uv.lock).
- **Frontend tests:** none (manual smoke during demo); coverage target applies to backend application code only.
- **Photosynthesis fixture:** generated by a committed `scripts/regenerate_fixture.py` so the README's "Maintaining fixtures" section points at reproducible bytes.
- **Qdrant unit tests:** in-process `QdrantClient(":memory:")`, no docker dependency in the unit suite.

Status legend: `[ ] todo` · `[~] in-progress` · `[x] done`. All tasks start `[ ] todo`; Phase 4 flips them.

### T04 — Tokenizer wrapper + section-aware `Chunker`

- **Status:** `[x] done`
- **Goal:** Implement the A10 chunking strategy: whole-section under the ceiling, paragraph-aware sub-chunking with overlap above it. Chunker takes a tokenizer callable (DESIGN §3) so the unit tests can use a deterministic fake.
- **Files touched:**
  - New: `backend/app/chunking/__init__.py`, `backend/app/chunking/chunker.py` (`Chunker`), `backend/app/chunking/tokenizer.py` (thin wrapper that lazily loads the SBERT tokenizer; *not* called by unit tests).
  - Modified: `backend/app/domain/models.py` (add `Chunk`).
  - New: `tests/unit/test_chunker.py`.
  - Modified: `.env.example` (add `CHUNK_SECTION_CEILING_TOKENS`, `CHUNK_SUB_SIZE_TOKENS`, `CHUNK_SUB_OVERLAP_TOKENS`).
- **Contract (DESIGN §3 `Chunker`, §4.5):** for each `Section`, if token count ≤ ceiling, emit one Chunk with the full section text; else walk paragraphs accumulating until `sub_size_tokens`, emit, rewind by `sub_overlap_tokens` snapped to a paragraph boundary, continue. Global `chunk_index` monotonic in document order. All F5 metadata fields populated. Never returns `[]`.
- **Tests added (covers DESIGN §7.1 `test_chunker.py` row, with fake tokenizer per the revision-1 cleanup):**
  - Fake tokenizer used throughout: `lambda s: list(range(len(s.split())))` (one token per whitespace-separated word).
  - Section with 50 "words" (= 50 tokens) and `ceiling=1000` → exactly one chunk; `chunk_index_in_section=0`; `text` matches the full joined section.
  - Section with 1200 "words", `ceiling=1000`, `sub_size=512`, `sub_overlap=64` → ≥3 chunks; consecutive chunks share ~64 tokens of suffix/prefix overlap.
  - Sub-chunk boundaries align with paragraph starts (no chunk begins mid-paragraph): assert each emitted chunk's first character matches the first character of one of the section's paragraphs.
  - Global `chunk_index` is `0, 1, 2, ...` across the whole article — no resets between sections.
  - F5 metadata: `section_title`, `section_index`, `chunk_index_in_section`, `char_offset_start`, `char_offset_end`, `text` all populated on every chunk. `char_offset_*` round-trip: `cleaned_body[start:end] == chunk.text` (within paragraph-snap tolerance — assertion encodes the tolerance explicitly).
  - Edge: a `CleanedArticle` with one section of one paragraph emits exactly one chunk.
- **Done means:** chunking is fully unit-tested with a fake tokenizer; the real SBERT tokenizer is loaded only when its wrapper is called (which won't happen until T10's lifespan or the integration test in T16).
- **Dependencies:** T03.
- **Delegation:** AI generates chunker + tests; I review the paragraph-snap logic (this is the easiest place to introduce off-by-ones) and verify the overlap math against §4.5.
